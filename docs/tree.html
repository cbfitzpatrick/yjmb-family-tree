YJMB Family Tree

About this site

The tree is rendered directly in your browser from protected structured data. Cards no longer need to be generated as image files on a developer computer.

Using the tree

Search by name, personal nickname, section nickname, year, or section; click a card for the person's full stored profile; and use Visualizer to load section-specific family trees. The +/− controls keep the point currently centered in the viewport in focus while zooming.

Cards and names

Cards are constructed in the browser from protected structured data rather than pre-rendered person images. Members can choose Given/Preferred Name, Personal Nickname, or both for the first-name portion of the card, and people with a changed surname can independently choose Family/Maiden Name, Married/Current Name, or both for the last-name portion. Personal nicknames and section nicknames are stored separately. Card icons are currently disabled for ordinary viewers; administrators can test the prepared icon set in Admin Mode → Feature Preview without publishing the icons.

Sections

Broad section categories control solid card colors arranged as light-to-dark ramps within each instrument family, while specific answers such as Alto Saxophone, Snare, Bass Drum, Rifle, Saber, or Flag are preserved. Drumline is treated as Battery and Pit as Front Ensemble.

When exactly one section is applied, every complete connected family containing at least one member of that section is shown and those trees are packed side-by-side. White cards are members only of the selected section, blue cards are relatives outside the selected section, and half-white/half-blue cards participated in the selected section plus another section.

Relationships

VET/RAT lines use the historical gray connector style. If a correction adds a RAT who is not yet in the directory, the protected updater creates that person's workbook row and writes the reciprocal VET at the same time. Claims involving an already-existing person remain one-sided until reciprocity is validated, so an existing profile is never silently overwritten.

Leadership

Marching-band leadership entries can be added/removed individually, classified as Formal or Informal, and may include optional year(s). Formal choices include Drum Major, Section Leader, Guard Captain, Staff Assistant, Operations, Props, Uniforms, Libraries, MCM, RAT Parent, and Other. Band Club leadership is tracked separately with its own optional position/year history. Card icons remain disabled for ordinary viewers for now; Admin Mode includes a Feature Preview tab for testing the prepared icon set before enabling it publicly. The set uses the supplied Section Leader and Band Club artwork, the supplied cap for RAT Parent/RAT Mom/RAT Dad, two black gloves for Drum Major, a camera for MCM, a book for Libraries, and a uniform for Uniforms.

Updating information

Add yourself is a direct-link page. Authenticated additions and profile corrections normally enter the protected automatic updater immediately; workbook conflicts are held rather than overwritten. Every applied change is written to the encrypted administrator changelog and can be safely reverted when no later edit conflicts.

Favorite Tech Band Memory and the rest of the profile live in the authoritative workbook. The protected site payload is rebuilt from that workbook, and the developer workbook export downloads the same updated workbook state, so the memory field is not an independent browser-only value.

Administration

Admin Mode uses the same separate developer key as protected workbook export, in addition to ordinary site access. There is no visible Admin button; the site owner can open it with Ctrl+Alt+Shift+A or YJMBAdminMode() in the browser console. It provides tree/card editing, a spreadsheet view, pending-request approval/denial, unreciprocated-connection validation, uncategorized-instrument mapping, encrypted changelog/revert, and workbook export. The admin key is kept only in memory for the open tab.

Site-only publishing

The project includes a UI-only publishing path that preserves the already-deployed encrypted tree bundle, allowing HTML/CSS/JavaScript changes without rebuilding tree data or touching the protected workbook.

Privacy

The public repository contains encrypted tree data rather than the plaintext master workbook. Access credentials, the developer key, workbook key, and tree decryption key are not stored in this page.
